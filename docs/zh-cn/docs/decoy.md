# 诱饵分区

诱饵分区把加密 Windham 分区藏在另一个可见可识别的分区之下——通常是 GPT 分区表的最后一个分区或磁盘尾部的空闲区域。外层分区和加密分区在磁盘上重叠：加密数据存放在外层分区空间的最末端、GPT 备份头区域之前。

## 威胁模型

如果有人强迫你交出磁盘内容，你可以指向那个看起来完全正常的可见分区，否认加密分区的存在。加密数据不带任何签名，只要外层分区足够大，那些"多出来的"看似随机的扇区可以被解释成文件系统本身的噪音；又或者是买来的二手硬盘上本来就残留着前任主人的格式化痕迹——这种情况并不罕见。

## 创建诱饵分区

```bash
# 第一步：用随机数据覆写整个磁盘（可否认性的关键前提）
sudo dd if=/dev/urandom of=/dev/sdb bs=16M

# 第二步：在磁盘开头创建可见分区（例如 FAT32）
sudo parted /dev/sdb mklabel gpt
sudo parted /dev/sdb mkpart primary fat32 1MiB 100%

# 第三步：在磁盘末尾创建诱饵分区（1 GiB）
sudo windham New /dev/sdb --decoy-size=1024
```

Windham 会读取 GPT 布局，找到最后一个分区的结束位置，然后把诱饵的加密头放在 GPT 备份区之前。

## 实现原理

1. Windham 读取位于 LBA 1 的 GPT 头以及分区条目数组。
2. 按结束 LBA 降序排列所有分区，找到**最后**一个分区。
3. 诱饵分区的结束扇区 = 最后一个分区的结束 LBA − 加密头区域（40 扇区）。
4. 诱饵分区从 `结束扇区 − 诱饵大小` 处开始，并对齐到块大小。
5. 加密头写入 `(最后一个分区结束位置 + 1 − 加密头区域扇区数) × 512` 处。

打开诱饵分区时需要使用 `--decoy` 标志：

```bash
sudo windham Open /dev/sdb --decoy
```

## 局限性

### 文件系统兼容性

外层文件系统必须**从低扇区到高扇区线性写入**数据。FAT32 和 ExFAT 通常满足这一要求。EXT4 以及大多数日志文件系统**不能保证**线性写入，随时可能覆盖外层分区末端的诱饵数据。

### TRIM / 丢弃指令

支持 TRIM 的 SSD 会定期丢弃不再使用的扇区。如果外层文件系统从未往诱饵区域写入过数据，SSD 可能把它标记为"已丢弃"，造成一个肉眼可见的数据空洞——这直接摧毁了可否认性。追求极致安全请使用 HDD 或不支持 TRIM 的 U 盘。

### GPT 分区表的修改

在创建诱饵分区**之后**调整分区表（新建、伸缩、删除分区）很可能导致加密头移位或被彻底覆盖。**创建诱饵分区后请不要再动 GPT 分区表。** 如果实在绕不开，请先用 `Backup` 备份加密头，再用 `Restore` 还原。

### 没有辅助数据区

诱饵分区不支持辅助数据区。辅助数据区需要紧接在加密头后面，而诱饵场景下加密头和可见分区末尾之间通常没有多余空间。

### 每个磁盘只能有一个诱饵分区

只有 GPT 表中**最后一个**分区可以承载诱饵分区。这是 GPT 解析器的硬性限制——它会把所有条目按结束 LBA 排序，只取最后那个。

## 安全性说明

- **创建诱饵分区之前，务必用随机数据覆盖整个磁盘。** 否则诱饵区域可能残留全零之类的明显模式，攻击者一眼就能识别。
- 诱饵分区的位置可以从 GPT 布局直接推算。如果攻击者事先知道可能存在诱饵分区，他能算准确位置。可否认性的底气就来自加密数据本身看起来与随机垃圾或普通格式化残留毫无区别。
- 追求最高级别的可否认性时，可以把诱饵分区建在一个**普通的 Windham 分区内部**——外层的加密头本身已经是随机数据，内部诱饵的加密头更容易融入背景。
