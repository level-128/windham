About Windham Web

Windham Web (Windham Emscripten Port) is an in-browser encrypted disk unlocker. Upload a FAT32 or exFAT disk image created by Windham, enter your passphrase, and browse, navigate, and download files — all decryption happens locally in WebAssembly. No data leaves your machine.

Creating a disk on any ISO C platform: GNU/Linux, macOS, *BSD, Zephyr, HarmonyOS, QNX, Windows, Redox OS and Nuttx.

windham New disk.img --diskfile="your size here" --create-exfat

Not all supported platform has Windham New enabled. Windham running under FreeRTOS (including ESP-IDF), UEFI EDK II, non-frontend mode or basically all bare-metal systems without an OS has New support absent.

Creating a FAT32 or ExFAT disk manually on GNU/Linux or Linux-kernel based OS with GNU compatible libc (musl …)

windham New disk.img --diskfile="your size here"
sudo windham Open disk.img --to="Optional name"
# FAT32
sudo mkfs.vfat -F 32 -n "your volume name" /dev/mapper/your_name
# exFAT
sudo mkfs.exfat -n "your volume name" /dev/mapper/your_name
sudo windham Close your_name

Note:
1. it is possible to pass block devices (e.g. /dev/sdx or /dev/nvme0nxpx) as disk image under UNIX. This is not recommended. No test has been made to cover all browser combos for such use case.
2. UEFI GPT partition scheme inside windham image is not supported. However, it is possible to create a protective MBR which contains FAT/exFAT partition range.
3. Windham Web only supports 128/256 bit AES-XTS encryption with block size 512, 1024, 2048 and 4096; dm-crypt compatible XTS scheme, little-endian XTS counter. This is the only supported encryption scheme under ISO C, and it is default under GNU/Linux regardless of the host endianness.
4. UEFI TCG OPAL is NOT compatible with Windham Web and windham ISO C.

Fold Backup

Download a compact 960 B backup containing a single keyslot. Suitable for paper or QR code recovery.

Backup credential

Passphrase backup stores the full password keyslot: restore with either the passphrase or the master key, and passphrase unlock keeps working. It runs the KDF once, so it is slower. Master key backup stores header metadata only (the keyslot area is random padding): restore with the master key alone, and the disk then unlocks with the master key only — no KDF, instant.
